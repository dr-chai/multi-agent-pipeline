# RBP 對拍對照表模板（fixture interchange）

> 用法：跑完 fixture 後，照下面表格填你哋嘅結果，回傳俾對拍方。
> 字段：`fixture_id | our_verdict | our_digest | expected_verdict | match | note`

| fixture_id | our_verdict | our_digest | expected_verdict | match | note |
|---|---|---|---|---|---|
| NEG-001 | REJECT | sha256:… | REJECT | ✅ | — |
| NEG-002 | INCOMPLETE | sha256:… | INCOMPLETE | ✅ | — |
| NEG-003 | REJECT | sha256:… | REJECT | ✅ | — |
| NEG-004 | REJECT | sha256:… | REJECT | ✅ | — |
| … | … | … | … | … | … |

## 字段說明

- **fixture_id**：負例嘅 NEG 編號（`NEG-001`～`NEG-015`，見 `9-19-fixture.md` §3.0 映射表）
- **our_verdict**：你哋實現跑出嚟嘅 verdict（例如 `REJECT`／`INCOMPLETE`／`HOLD`／`UNKNOWN`）
- **our_digest**：你哋實現對 fixture 內容算嘅 digest（`sha256:…`，如果適用）
- **expected_verdict**：fixture 聲明嘅預期 verdict（照 `rbp-negative-fixtures.json` 嘅 `expected.verdict`）
- **match**：`✅`（一致）／`❌`（不一致）
- **note**：**有 mismatch 嗰陣必填**——寫一句「點解唔一致」。例如：
  - 「我哋 verdict 名用 `Unknown(EXPIRED)`，你哋用 `REJECT(freshness)`，係同一個『過期』格、只係名唔同」
  - 「我哋未實現 side-channel 分類，判唔到 `exit_code_false_positive`」

## 規則

1. **唔好淨係報 match/mismatch**——mismatch 一定要帶 `note` 講「點解」，否則對拍冇信息。
2. **如實未實現**要寫「未實現」＋理由，唔好當 PASS。
3. **digest 對唔上**要寫「邊個 digest 唔同」＋「你哋用咩算法版本」。

## 格式

- Markdown 表格（人讀）或 JSON（機讀）都得。
- JSON 版：`[{ "fixture_id": "NEG-001", "our_verdict": "REJECT", "our_digest": "sha256:…", "expected_verdict": "REJECT", "match": true, "note": "" }]`
